“Unit not found” doesn't always mean “not installed”

Two systemd managers, one stray process, and an error message that pointed the wrong way.

← All projects

The problem

Restarting a service on my home server returned “Unit not found.” It read like the service was never installed.

What was really going on

Linux has two systemd managers: the system manager (sudo systemctl) and a per-user manager (systemctl --user). My server runs services under both. Asking the wrong one gives the same “not found” error.

Second trap

A hand-started copy of the dashboard was still holding its port. The proper service kept crashing with “address already in use.” After five tries, systemd's restart limit locked it into “start request repeated too quickly” — which looks like a broken unit, not a busy port.

The fix

  • Wrote down which services live under which manager, so nobody has to guess.
  • Stopped the stray process, then let systemd own the service so it starts on boot and restarts on failure.

Takeaway

Read an error for what it rules out, not what it suggests.
